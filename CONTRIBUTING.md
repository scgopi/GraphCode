# Contributing

Issues and pull requests are welcome.

## Licensing of contributions

`graphcode-cli/` are MIT. See [LICENSE](LICENSE) for which applies where.

**By submitting a contribution, you agree that it is licensed under the same terms as
the part of the project it changes**, and that it may be distributed under those terms
and under the MIT future licence each release converts to.

## Sign your work

Every commit needs a `Signed-off-by` line certifying the
[Developer Certificate of Origin](DCO) — that you wrote the change, or have the right to
submit it under the project's licence:

```sh
git commit -s
```

`-s` adds the line for you, using your `user.name` and `user.email`. This is a statement
about where the code came from, not a copyright assignment: you keep the copyright in
what you write.

## Before opening a pull request

- Run `make test`.
- Match the surrounding code — its naming, its structure, and its comment density.
  Comments should explain a constraint or a non-obvious *why*, not restate the code.
- Keep one change per pull request, and say in the description what problem it solves
  rather than what files it touches.

## Third-party code

Do not paste code from other projects. If a change is adapted from something with a
compatible licence, say so in the pull request so the notice in
`graphcode/Resources/Licenses.txt` can be updated — that file is generated by
`Tools/generate-licenses.sh` from the licences on disk.
